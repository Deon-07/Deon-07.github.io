2. In-Game Virtual Economy & Simulated Wallet Disclosures

📌 Plain-Language Summary

Every coin, dollar amount ($), gem, gas fee, and wallet prompt in this game is part of a fictional simulation. You cannot make real money playing this game. Entering a crypto wallet address on the profile screen only advances an in-game story quest and will never interact with real cryptocurrency or banks.

2.1 Fictional Arcade Scoring & Dollar Prefix Formatting

Throughout the Game's user interface, scores and virtual token rewards are formatted with a dollar sign prefix and three decimal places (e.g., format_money(val) -> "$%.3f", presenting values such as $0.050, $25.000, $100.000, or $500.000). You are explicitly notified that:

  • Zero Real-World Value: In-game points, balances, and gems are 100% fictional virtual entertainment tokens with zero real-world cash or monetary value ($0.00).
  • No Banking Services: The Application is not a financial institution, bank, money services business (MSB), cryptocurrency exchange, custodial wallet, or investment vehicle.
  • No Redemption: Virtual balances cannot under any circumstances be redeemed, exchanged, or cashed out for legal tender, cryptocurrencies, gift cards, or physical goods.

2.2 Simulated Cryptocurrency Wallet Address Storage

In the game's Profile Screen, players can enter an optional cryptocurrency wallet address string (e.g., Ethereum or Solana address format):

  • Technical Storage: The string is stored locally in user://jelly_data.json and synchronized to the cloud table public.player_backups.wallet_address.
  • Zero Blockchain Interaction: The Game contains zero Web3 libraries, zero cryptographic RPC nodes, zero private keys, and zero connectivity to any blockchain network.
  • Arcade Quest Milestone: The wallet input serves exclusively as an interactive milestone for an in-game progression quest.
  • Celebration Rewards: Completing the simulated 48-hour processing queue activates claim_simulation_rewards(), granting purely in-game digital perks: 30 days of ad-free gameplay, a permanent 2X VIP multiplier, and 100 of each consumable power-up (Bombs, Shakes, Doubles, Shields). Zero real-world money or cryptocurrency is disbursed.

3. Data We Collect and How We Collect It

📌 Plain-Language Summary

We collect two types of data: (1) what you create or provide (guest ID, optional username/email, high scores, merge stats, and booster inventory), and (2) technical details sent automatically by your phone (device model, Android OS version, IP address, and Google Advertising ID). We never collect credit cards or real home addresses.

3.1 Anonymous Guest Mode Data (Default)

By default, the Game does not require account creation or personal login credentials:

  • Guest Account Identifier: Format guest_WATER-XXXXXX, generated algorithmically via client-side XOR hashing of random integers and system timestamp entropy.
  • Referral Code: A 12-character string (e.g., WATER-XXXXXX) assigned to your device to facilitate optional friend referrals.
  • Guest Cloud Saves: Guest progress is backed up to our cloud database under this anonymous guest ID without requiring email verification.

3.2 Optional Registered Account Data (Supabase Auth)

If you choose to create a registered account or link your profile via our optional authentication screen:

  • Email Address: Stored securely in Supabase GoTrue authentication servers (auth.users) and mirrored in player_backups.email.
  • Password: Salted and hashed using secure bcrypt algorithms on the backend. We never see, log, or store plaintext passwords.
  • Custom Username: Player-selected public display name (e.g., "Jelly Champion"), indexed uniquely in the database.

3.3 In-Game Progression and Virtual Inventory Data

To provide continuous gameplay across sessions and devices, the Game synchronizes:

  • Scores & Progress: Virtual score balance (high_score), single-game record (top_score), merge count (total_merges), and rounds played (games_played).
  • Booster Inventories: Counts of Jelly Bombs (bomb_count), Container Shakes (shake_count), Double Multipliers (double_count), and Danger Line Shields (shield_count).
  • VIP Status: Active duration timer (vip_timer) providing in-game multiplier privileges.
  • Quest Metrics: Validation Gems collected (validation_gems), daily tasks (daily_tasks), stage objectives (stage_tasks), gas fee status (gas_fee_paid), rewarded ad counts (validation_ads_watched), and withdrawal simulation timestamps (withdrawal_requested_at, ad_free_until, is_simulation_completed).
  • Social Referral Data: Inviter referral code (referred_by_code), friend count (referral_count), and referral bonus points (referral_earnings).
  • Full Game State Snapshot: A complete JSON backup payload stored in player_backups.save_data.

3.4 Technical Identifiers, Device Specs & Advertising IDs

When the Game communicates with cloud servers and ad networks, the following technical data is processed:

  • Device Hardware: Manufacturer, model, CPU architecture (arm64-v8a), screen resolution, and available RAM.
  • Operating System: Platform (Android, iOS, Web), OS version, and API level (Android API 24 to 36).
  • Google Advertising ID (GAID / AD_ID): Resettable 32-character advertising identifier used for ad attribution, fraud prevention, and personalization.
  • Google Play App Set ID: Scoped identifier used for cross-app analytics within our developer account.
  • Network State & IP: Connection type (Wi-Fi/Cellular) and client IP address, used to infer coarse location (city/country).

3.5 Push Notification Tokens

If you grant notification permissions (android.permission.POST_NOTIFICATIONS), your Firebase Cloud Messaging (FCM) registration token is stored in public.user_push_tokens alongside your user_id, device platform, and app version to deliver retention reminders (2h, 24h, 48h) and remote gift broadcasts.

3.6 Local Sandboxed Storage

Local files are strictly sandboxed within user:// (/data/data/com.water.ball.merge.game/files):

  • user://jelly_data.json: Local JSON file of game state, scores, and quest milestones.
  • user://supabase_auth.json: Active session JWT tokens.
  • user://seen_notifications.json: History of viewed announcement IDs.
  • user://jelly_highscore.save: Legacy binary score file.

6. Data Storage, Retention and Security Architecture

📌 Plain-Language Summary

Your game backup is stored indefinitely on cloud servers so you never lose your high score or items when upgrading your phone. We do not automatically purge old data after a set period. If you want your account and cloud backup permanently deleted, you can request it by email, and our team will erase it within 30 days.

6.1 Cloud Hosting and Encryption

Cloud records are stored in enterprise-grade data centers managed by Supabase Inc. on Amazon Web Services (AWS). All communication between the Game client and backend servers is encrypted using Transport Layer Security (TLS 1.2 / TLS 1.3).

6.2 Indefinite Retention Policy

  • No Automated TTL: The database does not implement automated row expiration or background purge cron jobs.
  • Indefinite Storage: Player records in public.player_backups, scores, booster inventories, wallet strings, and referral data are retained indefinitely to enable players to restore their progress at any time.
  • Push Tokens: Retained in public.user_push_tokens until invalidated by Firebase Cloud Messaging or updated on a new device session.
  • Local Data: Retained in the application sandbox until you clear app data via device settings or uninstall the Game.

6.3 Technical Safeguards

We enforce PostgreSQL Row Level Security (RLS) policies on cloud tables, bcrypt password hashing via Supabase GoTrue, and protected local application sandboxing with allowBackup=false to prevent unauthorized access.
